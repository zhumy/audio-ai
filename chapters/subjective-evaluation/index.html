WHAT TO MEASURE

音频评价目标

Core Idea

主观评价首先定义听者要判断的构念

同一段降噪语音可能同时出现噪声更少、语音更失真、可懂度提高、自然度下降、长期聆听更疲劳等现象。 如果实验只问“哪段最好”，听者会把不同判断标准混在一起，结果看似是一个分数，实际构念并不清楚。

因此，本章的方法选择顺序是：先明确感知目标，再选择主观范式；先判断是否需要参考信号， 再选择客观指标；最后用人耳评价校准客观指标的适用边界。

Blind Listening

同一组音频，换问题就会换答案

课堂可用四段同内容语音导入：原始带噪、温和降噪、激进降噪、带宽受限或编解码失真。 第一轮只问“哪段最好”；第二轮分别问“哪段最容易听懂”“哪段人声最自然”“哪段背景最干净” “哪段最适合连续听十分钟”。学生通常会发现答案发生变化。

这说明评价实验不是先选指标，而是先规定听者究竟评价什么。

评价目标 典型问题 典型方法或指标
总体质量 整体听起来有多好？是否愿意接受这个处理结果？ MOS、P.835 OVRL、POLQA、ViSQOL、DNSMOS
语音信号质量 人声是否自然、清晰、无失真、无断裂？ P.835 SIG、主观自然度评分
背景噪声质量 噪声是否明显、烦扰、起伏，是否有音乐噪声或处理伪影？ P.835 BAK、噪声侵扰度评分
可懂度 听者能否正确听懂词、句子或关键信息？ 关键词正确率、STOI、ESTOI
偏好 两个系统中更愿意使用哪个？在目标场景中更偏向哪个？ A/B preference、成对比较
可辨别性 A 与 B 是否存在可靠可听差异？ ABX、三角测试
听觉努力或疲劳 是否需要费力理解？长期听是否疲劳？ Listening effort、任务表现、问卷

SUBJECTIVE METHODS

主观评价方法

MOS / ACR 单刺激绝对质量评分，输出多个听者评分的均值。
MUSHRA 有明示参考、隐藏参考和锚点的多刺激中间质量评价。
ABX 检验 A 与 B 是否能被可靠区分，不回答哪个更好。
P.835 把降噪语音拆成 SIG、BAK、OVRL 三个评分维度。
P.808 众包听测的实施与质量控制框架，不是新分数。

MOS：Mean Opinion Score 是统计结果，不是唯一协议

MOS 是多个主观评分的算术平均。语音质量中常见 5 级绝对类别评分： 5 为 Excellent / 优，4 为 Good / 良，3 为 Fair / 一般，2 为 Poor / 差，1 为 Bad / 很差。 MOS 常来自 ACR（Absolute Category Rating，绝对类别评分），但报告中不能只写“做了 MOS”。

MOS= 1N ∑ i=1 N xi

最基本的报告还应给出听者数量、素材数量、条件数量、随机化方式、播放环境、筛选规则、 均值/中位数/标准差、置信区间和统计检验。

MUSHRA：中高质量、多系统、有参考的比较

MUSHRA 全称为 MUltiple Stimuli with Hidden Reference and Anchor。 它通常在同一页面中呈现明示参考、隐藏参考、一个或多个低质量锚点，以及若干待测系统； 听者可自由切换、重复试听，并在 0-100 连续尺度上评分。

隐藏参考用于检查听者是否能识别最高质量条件；锚点用于建立评分范围，避免所有系统挤在高分区域。 因此，把多条无参考音频放在一个页面上让听者分别打分，不应直接称为标准 MUSHRA。

  • 多个系统
  • 差异较细
  • 中高质量区间
  • 有可靠高质量参考
  • 输出严格对齐

ABX：可辨别性检验，不是质量排序

听者已知 A 和 B，随后听到随机等于 A 或 B 的 X，并判断 X 是 A 还是 B。 ABX 的原假设是随机猜测，单次正确概率为 0.5。若进行 n 次并答对 k 次，可用二项分布计算尾概率：

p= ∑ i=k n ( n i ) 0.5n

“未达到显著”不等于证明二者完全相同；它只说明在当前听者、素材、设备和试次数量下， 没有足够证据拒绝随机猜测假设。

P.835 与 P.808：降噪维度和众包控制

P.835 面向含噪声抑制的语音通信系统，把评价拆成 SIG（Speech Signal Quality，语音信号质量）、 BAK（Background Noise Quality，背景噪声质量）和 OVRL（Overall Quality，总体质量）。

它揭示了降噪中的基本矛盾：降低噪声不等于提高语音质量。一个激进降噪器可能 BAK 很高， SIG 较低，OVRL 中等，因为背景干净并不能抵消人声断裂、金属感或过抑制。

P.808 解决的是众包环境下如何组织在线听测：耳机和环境检查、训练样本、金标准题、重复样本一致性、 最短作答时间、异常听者剔除、设备与环境元数据记录。它可以与 MOS、P.835 或其他明确任务组合使用。

MUSHRA 互动示例：语音修复任务

这里把语音修复看成一个有参考的质量比较任务：Reference 是未损伤的干净语音； 待测版本包含隐藏参考、低质量锚点和三个修复系统。学生先不知道每个版本身份，只根据“与干净参考相比的听感质量” 在 0-100 分之间评分，最后揭示条件身份。

Reference

干净语音信号。MUSHRA 中允许听者反复切换 reference，用它建立满分质量的听觉基准。

版本 A

待评分版本。请先听 reference，再听本版本，判断语音自然度、缺损修复和伪影程度。

版本 B

待评分版本。注意是否有过度平滑、频带缺失、断续感或人工合成感。

版本 C

待评分版本。这个版本可能很干净，但不一定忠实保留原始语音细节。

版本 D

待评分版本。MUSHRA 中通常包含一个低质量锚点，帮助听者使用完整评分范围。

版本 E

待评分版本。隐藏参考应接近 100 分；若被打得很低，说明任务理解、播放链路或听者可靠性需要检查。

这个演示用浏览器合成的类语音信号说明 MUSHRA 结构；真实实验应使用真实语音材料、统一响度、随机化页面顺序， 并记录每位听者对隐藏参考和锚点的评分。

OBJECTIVE METRICS

客观感知评价指标

全参考或侵入式指标

全参考指标同时输入高质量参考信号与待评价信号，代表包括 PESQ、POLQA、STOI、ViSQOL。 优点是有明确比较基准；缺点是在真实录音、生成式输出、未知干净语音或合理输出不唯一的任务中， “越接近参考越好”的假设可能不成立。

无参考或非侵入式指标

无参考指标只输入待评价音频，通过统计模型或神经网络估计质量，代表包括 DNSMOS 和 DNSMOS P.835。 它们适合真实录音、线上监测和大规模筛选，但严重依赖训练数据分布；预测分数不能直接称为真实 MOS。

指标 参考要求 主要预测目标 典型场景 关键限制
PESQ 全参考 窄带/宽带语音听感质量，常见输出为 MOS-LQO 映射。 传统编解码、语音增强论文复现。 P.862 系列已于 2024-01-05 被 ITU 删除；当前通信语音质量客观评价应转向 P.863 系列或说明继续使用 PESQ 的理由。
POLQA 全参考 语音通信听感质量，输出 MOS-LQO。 现代语音通信、宽带与超宽带系统。 不是可懂度指标；需要规范实现和合适的通信语音使用条件。
STOI / ESTOI 全参考 语音可懂度，通常输出 0-1 范围的相关量。 噪声语音、增强算法、听力研究。 不衡量自然度、舒适度、总体音质或背景噪声烦扰度。
ViSQOL 全参考 语音或通用音频感知质量，输出 MOS-LQO。 编解码、语音与通用音频质量比较。 对模式、采样率、参考质量、对齐、静音比例和声道处理敏感。
DNSMOS 无参考 单条语音的主观质量预测。 真实降噪语音、大规模筛选、线上监测。 训练域偏差、语言和新型失真类型会影响泛化；不能代替最终听测。
DNSMOS P.835 无参考 预测 SIG、BAK、OVRL 三个分数。 降噪算法快速比较和问题定位。 仍是模型预测，不等于真实 P.835 主观实验。

不要把非感知指标误当成人耳质量

SNR、SI-SDR、MSE、频谱距离等主要描述信号误差或重建保真度。它们可以帮助诊断算法， 但不直接等于主观音质：波形误差小的输出可能有强烈音乐噪声；与参考波形不同的生成式增强输出也可能听起来自然。 因此它们应与感知代理指标和人耳评价分层使用。

EXPERIMENT DESIGN

主观评价实验设计

从研究问题开始，而不是从指标开始

不要写“比较算法 A 和算法 B 哪个更好”。研究级问题应明确任务、素材、条件和构念： 例如“在中文近讲语音、三类非平稳噪声和 0/5/10 dB 信噪比下， 比较两种降噪算法的语音质量、背景噪声质量和总体质量”。

是否能听出差异？

用 ABX；结论是可辨别性，不是质量优劣。

多个中高质量版本且有参考？

用 MUSHRA；保留明示参考、隐藏参考和锚点。

降噪语音需要区分人声与背景？

用 P.835；分别报告 SIG、BAK、OVRL。

单刺激总体质量或真实录音？

用 ACR/MOS；若在线众包，加入 P.808 质量控制。

控制刺激、听者与统计报告

主观实验不是把音频发给听者打分那么简单。刺激应统一内容、时长、响度或播放增益，避免削波和文件名泄露身份； 条件与页面顺序要随机化，素材要覆盖多个说话人、语句、噪声和难度。

听者需要训练样本、耳机和左右声道检查、注意力或听力筛查；排除标准应提前规定。 结果至少报告听者数量、刺激数量、每条件评分数、均值/中位数/标准差/置信区间、 筛选与排除数量、统计检验、效应量、多重比较校正，以及按素材或听者的 bootstrap 或混合效应处理。

研究级数据通常同时嵌套听者、语句、说话人、噪声和算法等因素；把同一听者的多次评分全部当作独立样本， 会高估结论稳定性。

名称错误：没有参考和锚点，却把多条音频评分称为 MUSHRA。

构念错误：用 ABX 判断哪个系统更好，或用 STOI 证明自然度提高。

统计错误：只报告平均分，不报告置信区间、样本量和多重比较。

控制错误：不做响度匹配，听者实际在选择更响的版本。

筛选错误：先看结果，再决定剔除哪些听者。

指标错误：把 DNSMOS 输出直接称为真实 MOS。

HISTORICAL LINEAGE

音频质量评价的发展脉络：从传输损伤到听觉体验

不是旧标准被新标准简单替代，而是评价对象不断扩张

音频质量评价的发展，并不是从“没有主观评价”发展到“开始评价音质”，也不是旧标准不断被新标准完全替代。 更准确地说，它是评价对象不断扩张、评价维度不断细化的过程：从物理信号是否正确，到传输或编码造成多少损伤； 从人耳总体觉得好不好，到究竟是语音、背景、空间特征还是交互体验出了问题；再到复杂 AI 音频是否自然、可信、忠实并适合具体任务。

  • 物理信号频响、带宽、电平、SNR、失真。
  • 总体 MOS人总体觉得电话语音好不好。
  • 客观预测机器预测听者会给出的总体质量。
  • 多维诊断语音、背景、响度、断续、音色等分开看。
  • 真实交互通话、延迟、双讲、听觉努力。
  • AI 音频自然度、忠实度、身份、空间和任务表现。

方法论主线可以概括为：从系统中心走向听者中心，从单一分数走向多维诊断， 从受控实验室走向真实使用场景，从有参考比较走向无参考感知预测。

Stage 1

设备和传输链路中心：信号损失了多少

早期电话系统主要由相对线性的模拟传输链路构成。工程评价首先关注频率响应、信号电平、 信噪比、谐波失真、串音、带宽、线路衰减和噪声功率。核心问题是： 输入信号经过线路、设备或网络后，物理上发生了多大变化？

这种方法适合分析线性滤波、增益变化和加性噪声，却无法完整解释人的听觉体验。 相同的频谱误差或 SNR 变化可能产生完全不同的主观影响；反过来，波形变化明显的两个信号也可能听起来几乎没有差别。

P.80 / P.800

标准化主观评价：人总体觉得好不好

电话网络需要能直接反映用户感受的统一标尺，于是形成 P.80 以及后来的 ITU-T P.800 主观评价体系。 P.800 规范传输质量主观评价中的听者、语料、播放环境、评分尺度、测试程序和统计报告。

这一阶段的代表输出是 MOS。听者听取一段语音后，按照“优、良、一般、差、很差”等等级评价整体听音质量。 早期 MOS 已经包含总体质量概念：综合考虑各种听到的失真后，这段电话语音整体有多好、是否可接受。

局限也很清楚：总体 MOS 可以告诉我们系统 A 比系统 B 好，但不能告诉我们究竟为什么好、哪里出了问题。

P.830 / BS.1116

数字编解码器：传统物理指标解释不了新的失真

数字语音编码普及后，失真不再只是简单噪声或频响变化，而开始出现量化失真、编码伪影、 频谱细节缺失、帧擦除、语音活动检测截断、多次转码、包丢失和时延变化。 ITU-T P.830 可以看作 P.800 通用框架在数字语音编解码器评价中的专门化。

通用音频和广播领域也形成另一条路线。ITU-R BS.1116 面向高质量音频系统中的细微损伤， 要求严格控制实验环境，以检测接近透明编码条件下的小差异。

从这里开始，语音通信和通用音频逐渐形成两条相关但不同的标准体系： ITU-T P 系列偏电话、通信和语音质量，ITU-R BS 系列偏广播、音乐和通用音频质量。

PSQM / PESQ / POLQA

从真人评价到客观感知模型：机器能否预测 MOS

标准化主观听测可靠，但成本高、周期长、难以实时运行。因此研究转向： 能否让算法模拟人耳，把参考信号和退化信号进行比较，自动预测听者会给出的总体质量分数？

ITU-T P.861 / PSQM 主要面向电话带语音编解码器，用心理声学模型估计编解码损伤的主观影响。 P.862 / PESQ 进一步面向窄带电话网络和语音编解码器的端到端质量，增强对时延、时间对齐、网络损伤和复杂失真的处理能力。 当前通信语音质量客观评价已转向 P.863 / POLQA 这一代。

这一阶段完成的是“真人总体评价 -> 机器预测真人总体评价”，但还没有从根本上解决“为什么不好”的诊断问题。

P.835 / P.806

从单一总体分数走向多维质量：究竟哪里不好

随着回声消除、自动增益控制和噪声抑制进入通信终端，单一 MOS 越来越难以解释系统表现。 特别是在降噪中，算法可能同时减少背景噪声又增加语音失真。只问“整体质量如何”时， 有人更讨厌噪声，有人更讨厌语音失真，评分权重不一致。

P.835 将降噪语音拆成 SIG、BAK、OVRL 三个维度。P.806 则进一步采用多个评分尺度， 除总体质量和响度外，还评价与质量退化相关的感知属性，以诊断总体质量下降的具体原因。

核心变化不是“开始评价音质”，而是从给出一个最终分数，发展到解释这个分数是怎样形成的。

P.804 / P.805

从单向听音走向真实会话：听着不错是否等于通话好用

P.800、P.830、P.835 等方法多属于 listening-only 评价：听者播放预先录制好的语音，但不真正参与交流。 实际通话体验还包括端到端时延、回声、双讲、抢话与打断、自己声音反馈、说话是否费力、对话节奏是否自然。

因此，P.805 发展会话质量评价方法，通过更接近实际服务的会话任务评价通信质量； P.804 则进一步从听、说和交互等阶段诊断会话语音质量。评价对象由“声音片段”扩展为“交流过程”。

BS.1534 / MUSHRA

通用音频路线：从透明编码到中等质量和多媒体

音乐、广播和通用音频并不总能用电话语音标准评价。BS.1116 适合高质量音频系统中的微小损伤； 但互联网流媒体、数字广播、移动多媒体和低码率音频常处于中等质量范围，差异更大、系统更多。

ITU-R BS.1534 / MUSHRA 用隐藏参考、低质量锚点和多个待测系统比较中间质量音频。 因此，MOS、MUSHRA 和 P.835 不是“低级到高级”的线性关系，而是分别适配不同评价任务： MOS 用于单刺激总体质量，MUSHRA 用于有参考条件下多个系统的相对质量，P.835 用于降噪语音的语音、背景和总体质量分解。

P.808 / DNSMOS

从受控实验室走向众包，从有参考走向无参考

随着算法迭代速度加快，统一实验室、耳机、播放电平和监督流程难以支持大规模评价。 ITU-T P.808 建立互联网众包语音质量评价框架，将设备检查、训练、质量控制、异常听者筛选和结果报告纳入流程。

同时，PESQ、POLQA 等传统客观模型通常需要干净参考语音，而真实会议、手机录音、直播和用户上传内容往往没有参考。 DNSMOS 和 DNSMOS P.835 等模型使用大量真人评分训练神经网络，从单条语音预测质量或 SIG/BAK/OVRL。

P.808 改变的是“怎样获得评分”，DNSMOS 改变的是“没有参考时怎样预测评分”。二者都不是人耳本身。

AI AUDIO ERA

当前阶段：从“音质”走向复杂的人类体验

AI 音频让评价对象再次复杂化

当前音频系统已经不只是对原信号进行压缩和传输，而越来越多地包含深度学习降噪、生成式语音增强、 声源分离、语音修复、音色转换、空间音频、沉浸式通信、个性化听觉补偿、语音交互和智能代理。

生成式增强尤其会带来传统指标难以处理的问题：听起来更自然但与原始语音不完全一致； 噪声更低但改变了辅音或词语；总体质量较高但说话人身份漂移。 此时，单个总体质量分数很难回答所有问题。

现代评价通常需要组合证据

现代音频评价往往要同时考虑整体质量、前景声音自然度、背景质量、可懂度、自然度、忠实度、偏好、 听觉努力、空间质量、会话质量、语义准确性和身份保持。它们分别回答不同问题，不能互相替代。

最稳妥的证据链通常是：信号误差指标 + 感知客观指标 + 多维主观评价 + 任务正确率 + 真实使用场景测试。

评价维度 回答的问题 为什么 AI 音频中更重要
Overall quality 整体听起来好不好。 仍是产品体验入口，但不能单独解释问题来源。
Signal / Background quality 前景声音是否自然，背景是否干净、稳定、可接受。 增强系统常在降噪与语音失真之间做权衡。
Intelligibility 内容能否正确听懂。 可懂度提高不必然意味着自然度、舒适度或忠实度提高。
Naturalness / Fidelity 是否像真实声音，是否忠实于原内容和说话人。 生成式模型可能产生自然但不忠实的输出。
Spatial quality 方位、距离、宽度、包围感是否正确。 空间音频和沉浸式通信不能只用单声道语音质量指标评价。
Conversational quality 实际交流是否自然流畅，是否费力。 低延迟、双讲、回声和交互节奏会决定真实使用体验。
Semantic accuracy / Identity preservation 处理后是否改变语言内容，是否保留说话人身份和音色。 生成式增强、修复、分离和转换需要防止“听着好但内容错”。

THREE-LAYER WORKFLOW

工程与研究中的三层评价框架

1

信号与系统正确性

先排除工程错误：削波、电平、时延、采样率、频响、SNR、SI-SDR、实时率和算法稳定性。 这一层回答“系统有没有基本做对”。

2

感知代理指标

用 POLQA/PESQ、STOI、ViSQOL、DNSMOS 等做大规模快速比较和问题定位。 这一层回答“在指标假设成立时，系统可能怎样被人耳评价”。

3

人耳评价与任务验证

用 MOS/ACR、MUSHRA、ABX、P.835、P.808 众包控制、真实任务理解率、偏好和听觉努力验证最终体验。 这一层决定算法是否真正改善人的使用感受。

本章最终结论

音频质量评价的发展，不是从“信号损失”简单走向“Overall quality”，因为总体主观质量在早期 MOS 体系中已经存在。 更准确的脉络是：早期评价关注通信链路和编解码器是否损害总体听音质量；随后通过感知模型预测这一总体质量； 当降噪、回声消除和复杂处理出现后，又进一步把总体质量拆解为语音、背景和具体失真属性； 今天则扩展到会话交互、空间体验、自然度、内容忠实度和真实任务表现。

评价问题已经从“这个系统有没有损伤声音？”发展为“这个系统在具体场景下，是否真正改善了人的听觉体验和任务表现？”
